### 2. 接收与运动准备

1. `NetRecv_PlayerMove` 保留原签名、旋转更新、硬控和冲刺优先级及现有状态导航。普通远端跳跃由立即 `DoJump` 改为登记待跳和必需参数；普通事件更新当前目标但不覆盖待跳参数。消费前出现多次跳跃时保留首个，其他折叠。本地行为不借此修改。

3. `Approaching.PlayerMove` 的既有远端存活分支调用 `AdjustDestinationMotion()`，保留宠物、基础动画、远端 return 和本地路径。仅有待处理事件时进行速度准备，继续使用现有 `Destination`、`HandleWalking`、状态 `Move` 标签和 `MoveTo`；不改成每帧重启导航。
4. `AdjustDestinationMotion()` 根据当前目标及当前速度准备 CA 基线运动，再消费待跳。现有水平速度有效而目标方向为零时不将其清零；`Acc=0` 不等于水平速度为零，也不能据此构造跑跳方向。确认允许起跳时设置本次保存的 `Acc`、`JumpZ`，并按原跳跃处理清除 `bJustDamaged`，然后尝试 `DoJump` 一次；已处于 Falling、失权或起跳失败时直接消费，不等待落地重试。实际接收和消费阶段需核对原有写入时机对动作的影响。
5. CA 的基础动画速度原式为 `FMax(1.0, NewGroundSpeed / Pawn.Default.GroundSpeed)`，并同步 `CurrentAnimSpeed`。实施时核对其适用分支和默认地速，分母有效才按该公式更新；无效时保留当前动画速度，不引入额外倍率。此处只处理普通基础动画，不改变技能和跳跃播放倍率。
6. 在同一候选中退出接收分段倍率、旧快照写回、通用大误差瞬移，以及远端 `PlayerMove` 中的旧恢复和通用防卡 `Z+100`。新登记、消费和旧写入停用必须同时闭环。

CA 原式对速度取值和三维方向的限制见技术方案。首版保持对应关系，零方向和时间保护除外；不要同时改写限速、走路跳高或导航节流，再把结果称为 CA 原式。

### 3. 时间样本

沿用 CA 的本地帧时间累计，该值不等于服务端发包间隔。增加一个首样本标记；首次处理、重新接管后的首次处理，或累计时间 `t <= 0.001` 秒、`t > 1.0` 秒时，不执行 `距离 / t`：保留当前有效水平速度；没有有效水平速度则不主动赋予跑速，由现有 `MoveTo` 和物理继续推进。每次处理后清零累计时间并建立下一次样本；失权或重新初始化时清零并重置首样本标记。

`0.001` 和 `1.0` 秒是为避免极短除法及长时间静止后首动使用过期分母而暂定的采样保护值，不是协议超时或跳跃过期时间，尚未经游戏验证。首动无法推进、速度异常或低帧率效果不佳时记录现象并针对性调整，不扩展为断流预测或重试体系。

### 4. 状态和生命周期

消费前检查 Pawn、存活、普通运动控制权与物理状态；明确失权、死亡、重新 Possess 或销毁等会使待跳失效的路径清除待跳和时间样本，重新接管时重新采样。根据现有调用关系核对实际入口，复用确有必要的简洁内部清理，不为每一种理论状态建立独立状态机。硬控和冲刺保持现有优先级和业务规则。

`Knockbacking` 继承导航并调用父级 `PlayerMove`，新速度准备不得在仍处于击退状态时抢占控制权；但当前接收事件对非攻击、摆摊及硬控分支可能直接 `GotoState('Navigating', 'Move')`，进而退出击退。首版保留现有接收状态分支，**不承诺修复这一既有行为**；若要改变击退期间的目标更新或状态切换，须单独讨论其行为影响并验证。其他特殊状态同样以现有逻辑为基线，不为清理待跳顺带重写业务状态。

首版不新增落地观察状态，保留现有 `Landfloor` 和各状态覆盖的行为，不因防卡引入落地回调改造。落地后目标是否继续、攻击和其他状态是否受影响列入运行对照；发现目标丢失等可复现问题后另行确定最小修复。

# 金龙动作光效设计（D17）

状态：环绕加速已实现并编译；以下是光效实现设计，当前交付尚未启用新增光效。

## 视觉与动作配合

沿用 D15 的 OrbitSwimV5，保留模型尺寸、宠物间距、逆时针回归。环绕及回归周期由 3.5 秒改为 2.625 秒，角速度增加 1/3；身体动画仍为 3 秒循环，避免爪部和咬合变得急促。

| 层次 | 设计 | 首轮试调参数 |
| --- | --- | --- |
| 龙身金泽 | 头颈、背脊、尾根 6–8 处小范围暖金柔光，留出鳞片与肢体轮廓 | 暖金 RGB 255/190/55，低亮度，局部尺寸约 6–12 世界单位 |
| 脊背流光 | 亮度从颈部依次传向尾部，与身体波动错相配合 | 以动画帧为相位，亮度约 ±15%，不整条同步闪烁 |
| 黄色雷电 | 相邻背脊锚点、爪尖和尾端之间出现短电弧 | 淡黄芯、金黄边；每次 0.08–0.16 秒，间隔 0.35–0.7 秒，同时至多 2 条 |
| 尾端余光 | 少量短命金色光点随尾尖甩动 | 寿命 0.15–0.25 秒，最多 6–10 颗；起跑加速时仍保持短尾迹 |

头部只点亮角根和颈背；嘴部咬合保持可见。龙须已有飘动，首版不增加粗大光带。龙爪发光范围贴近爪尖，不扩成四团火球。电弧只连接龙自身相邻部位，避免跨过角色身体。颜色与范围为首轮试调值，需游戏中确认，不是已验证的成品效果。

## 骨骼跟随与状态

新增非 native 的 GoldenDragonBodyFxLink 管理资格与生命周期，GoldenDragonBodyGlow / GoldenDragonArc 管理显示；不在 native Guardian/Hero 上追加字段。由现有 Guardian helper 关联实际 Dragon，直接读取动画后的骨骼坐标，不能只跟随 actor 原点。具体骨骼名从现有 PSA 的 BONENAMES 导出，按头颈、脊背、四爪、尾部建立明确映射。

柔光使用深度测试的附加粒子层，保留原模型材质；首版不启用场景动态照明。电弧两端每帧跟随对应骨骼，以有限分段扰动模拟闪电；UE2 BeamEmitter 的端点更新方式先用本项目可编译接口验证，再确定实现，不假设新版引擎 API 可用。

站立环绕与逆时针回归连续更新光效，不因切状态重新爆闪；回到右侧跑动后保留贴身柔光，减少尾光密度。资格新增约 0.3 秒渐入；卸装、死亡、隐藏、收宠和换地图及时清理。粒子消失不能影响龙的动作。

## 所有玩家可见的接口

现有 BlackGoldWeaponFxLink.ResolveItem 依赖该人物 Controller.PSI.WornItems；文档已指出远端可能只有外观数据，因此它不构成已验证的全员同步接口。可复用其独立 helper、重试与清理方式，不直接复用词条资格函数。

服务端需给观察范围内客户端发送角色标识与 GoldenDragonSetEligible 状态，首次入视野、重登/换图以及穿脱/幻化变更均更新；客户端按对应角色缓存资格。此字段是拟定的业务状态，并非已有协议字段。实施前需定位当前角色外观/状态同步扩展点，确认可用消息承载与角色 ID 映射，不能随意占用 native 字段或声称新增 replication 块即可与 Lua 服务端通信。

缺失或未收到资格时，只保留普通环绕。每个观察客户端为该角色的实际 Guardian 创建同样的本地光效，电弧随机细节允许不同。未来如需美术预览开关，必须仅用于测试且默认关闭，不作为正式资格判断。

## 实施与验收顺序

1. 制作贴骨柔光和短电弧，单龙近景检查头、爪、尾动作不被遮住。
2. 落实服务端资格与观察者同步接口，再接入正式开关。
3. 验证各职业完整套装、缺一件、跨职业混搭、穿脱、幻化、重登及新进入视野。
4. 两个客户端互看：普通玩家仅环绕，套装达标者出现光效；自己的资格不能套到别人身上。
5. 检查左侧起跑回归、急停、转向、死亡、收宠；多龙同屏测帧耗，远景减少粒子而不降低龙模型 LOD。
